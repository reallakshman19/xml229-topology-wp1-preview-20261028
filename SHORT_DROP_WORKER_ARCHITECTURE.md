# Topology short-element UI responsiveness — architectural repair candidate

## Symptom and source basis
Owner supplied a private 898,252-byte PSI116 XML with 41 branches and 1,654 Node occurrences. A local read-only owner grouping finds 130 GASK groups with source spans ≤6 mm. This is a screening count, **not** a certified count of eligible removals. The original source is not uploaded to this repository.

The prior workspace used a direct main-thread import of `engine.js`, which executes the Pyodide topology Python stage. Selected element drops invoke repeated full transactions and topology reanalysis; Python/WASM work on the UI thread can prevent paint, navigation and cancellation. The preview button synchronously rendered all candidates, without paginated navigation, making it hard to distinguish opening a preview from a blocked operation.

## Architecture
1. `topology-worker.mjs` owns the Pyodide engine strictly for PSI116 `topologyPreFinalOnly` jobs. It refuses native CII/Final, enriched output and Weight transfers. The shared engine and Python transaction are unchanged.
2. `topology-worker-client.mjs` creates one dedicated, disposable module Worker per mounted topology workspace. It correlates request IDs, rejects worker crash/timeout, terminates on cancel or source replacement, and rejects late responses. It also recycles an idle Worker after eight completed jobs to reclaim Pyodide scratch memory. Unsupported Worker environments fail closed rather than falling back to main-thread Python.
3. `workspace-app.mjs` keeps the source-authoritative plan/short candidates unchanged. Clicking the short preview runs **no Python** and builds at most 24 candidate rows. Selected source IDs persist across pages. The preview is explicitly labeled as nonmutating and scrolls into view.
4. Apply **all selected (89/89 if 89 are selected)** without repainting or reselecting in the UI. The headless `short-bulk.mjs` orchestrator still performs one owner per atomically validated transaction inside the topology Worker, checks fresh source IDs/SHA, verifies complete pre-Final lineage, and reuses the transaction's authoritative `after_result` reanalysis. The canvas and audit panel publish once when complete or safely stopped.
5. Each selected owner is either validated, skipped with a source-qualified reason, explicitly failed, or unprocessed after a safe stop. Status reconciles all four buckets against the immutable original selection, while the changing eligible-on-current-XML count is labeled separately. The audit/canvas are visibly labeled **pre-batch snapshot** while jobs run. A one-second elapsed-time heartbeat avoids a static `APPLYING` banner; **Cancel** terminates the Worker. Last pre-Final-verified XML and receipts remain available. A worker timeout (180 s per atomic job), crash or validation failure stops without publishing unvalidated bytes. The old eight-owner UI cap is removed; Worker recycling every eight jobs remains only a memory boundary.
6. To bound browser memory, every full source-occurrence map is checked by Python then held in the browser as its exact SHA-256 digest, mapping count and source-linked operation receipts. The full per-pass map is reproducible from the original XML and the recorded source-ordered transactions; a compact hash is *not* a substitute for original-source authentication.

## Safety and unchanged policy
- No change to ≤6 mm removal qualification, straight two-port length evidence, allowed component types, bore/facing checks, 25 mm automatic closure policy, Weight custody, source references, restraints, or source-lineage gates.
- No new auto-approval: preview is nonmutating; explicit selection and Apply remain mandatory.
- A user's original file is never overwritten; no native CII, O1, Final, or Weight master is released.
- Sequential validated passes remain separate, not combined into an unchecked multi-owner operation.
